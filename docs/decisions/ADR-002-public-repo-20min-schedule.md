# ADR-002 リポジトリを公開にし、20分おきに戻す

- 状態: 決定（2026-11-17、持ち主が承認）
- 置き換える範囲: ADR-001 の「動かす場所（非公開）」と「実行頻度（毎時）」。ほかの決定は ADR-001 のまま
- 根拠: クラウド側の Claude との 2026-11-17 の検討（`docs/sources.md` の「実行環境」「大会の仕組み」）

## 決めたこと

| 項目 | 決定 |
|---|---|
| 公開・非公開 | 公開（`orbiane/forecast-lab`） |
| 実行頻度 | 20分おき（毎時7・27・47分 UTC。見本と同じ） |
| ログ | 環境変数 `HIDE_FORECASTS_IN_LOGS=true` のとき、`main.py` の INFO ログ（調査内容・理由・予測値）を止める。実行の要約は、問題の URL・軽い誤りの件数・費用と時間の見積もりだけにする（`bot_helpers.log_public_summary`）。失敗の表示は例外の種類だけにする |
| 60日ルール対策 | `.github/workflows/keepalive.yaml` が毎月1日に `docs/keepalive.log` へ1行足して `main` に push する（`BOT_ENABLED` が `true` のときだけ）。CLAUDE.md の「`main` への push は持ち主の承認後」の例外として、持ち主が承認した |
| コミットのメール | 持ち主の Mac でのコミットに本物のメールアドレスが載らないよう、GitHub の設定でメールを非公開にする（持ち主の作業） |

## 理由

- 毎時1回では問題を逃しうる。2025年Q1は、10問が一斉に出てその1時間の終わりに締め切られた。2026年春は、締め切り前の約1.5時間がボットの受付時間だった。GitHub の定時実行は混雑時に遅れることもある
- 非公開のまま20分おきにすると、Actions の無料枠（月2,000分）を超える。公開なら無制限
- オープンソースのボットはクレジットが約2倍になる（要約経由の情報）。賞金を受け取るにはどのみちコードを Metaculus に見せる
- 公開すると実行ログも誰でも読める。受付中は Metaculus がボットの予測を隠しているので、ログで漏らさないようにした
- 公開リポジトリでは、60日間動きがないと定時実行が黙って止まる。ボットは自分でコミットしないので、月1回の記録で防ぐ

## 捨てた案

- 非公開＋Mac Studio で20分おき（launchd での定時実行）: 無料でログも漏れないが、Mac Studio の電源やネットが切れると止まる
- 非公開＋GitHub で20分おき: 無料枠を超えて追加料金がかかる
- 非公開＋毎時（ADR-001 の設定）: 問題を逃しうる

## まだ怪しい点

- `forecasting-tools` や `litellm` の内部が、INFO や ERROR のログに LLM の出力を出すかは、全部は確かめていない。初回の Test Bot のログで確かめる（`KICKOFF.md`）
- `GITHUB_TOKEN` による push が、60日ルールの「動き」に数えられるか（要確認）。数えられないなら別の方法に変える

## 見直すとき

- ログに予測値や理由が漏れているのが見つかったとき
- keepalive の push が失敗した、または定時実行が止まったとき
